1Vue d'ensemble

Le système a deux parties :

  • Les boîtiers (Raspberry Pi + lecteur NFC) : un par professeur, plus un boîtier d'accueil au secrétariat pour associer les cartes. Chaque badge est d'abord écrit sur la carte SD du boîtier, puis envoyé au serveur toutes les 10 secondes. Sans réseau, le boîtier garde les badges et les envoie plus tard.
  • Le serveur (ce site + une base PostgreSQL dans Docker) : il reçoit les badges, importe l'emploi du temps d'ADE et calcule les présences.

Deux sortes de comptes : le compte administrateur (défini dans le fichier .env du serveur, accès à tout) et un compte par professeur (accès à ses cours uniquement).

2Checklist de rentrée

  1. Fin d'année : faire partir les BUT3 et passer les promos à l'année suivante (section 7).
  2. Étudiants : importer la liste des nouveaux BUT1 (tutoriel secrétariat).
  3. Emploi du temps : {{ bouton("Synchroniser l'EDT", "arrow-repeat") }} dans la page Emploi du temps.
  4. Professeurs : créer les comptes des nouveaux profs et leur attribuer un boîtier (sections 3 et 4).
  5. Cartes : faire associer les cartes des nouveaux étudiants au secrétariat, sur le boîtier d'accueil.

4Déclarer un boîtier

Menu utilisateur (en haut à droite) → Configuration, carte Boîtiers.

{{ capture("a-config-boitiers", "Configuration : la liste des boîtiers avec leur professeur, leur salle de repli et leur token.") }} {% call etape(1, "Ajouter le boîtier") %}

Saisissez son identifiant (ex. RPI-001), choisissez le professeur attitré et une salle de repli, puis ajoutez.

  • Un badge est relié au cours du professeur du boîtier à cette heure-là ; à défaut, au cours qui a lieu dans la salle de repli.
  • Case SAE : rattache les badges aux séances de SAE du groupe de l'étudiant (boîtier d'un projet, sans prof fixe).
  • Case Accueil : c'est le boîtier du secrétariat, le seul proposé par « Scanner la carte ».
{% endcall %} {% call etape(2, "Copier le token") %}

Le token est le mot de passe du boîtier auprès du serveur. Bouton pour le copier, il sera collé dans le fichier .env du boîtier (section 5). en génère un nouveau (en cas de boîtier volé) : il faut alors le recopier sur le boîtier.

{% endcall %}

5Installer un boîtier Raspberry Pi

{% call etape(1, "Préparer la carte SD") %}

Avec Raspberry Pi Imager, installez Raspberry Pi OS Lite (sans bureau : démarrage plus rapide). Dans les options : nom d'utilisateur pi, Wi-Fi de l'IUT, SSH activé.

{% endcall %} {% call etape(2, "Brancher le matériel") %}

Numéros GPIO en mode BCM :

ÉlémentGPIO (BCM)Broche physique
Lecteur RC522 : SDA, SCK, MOSI, MISO, RST8, 11, 10, 9, 2524, 23, 19, 21, 22
RC522 : alimentation 3,3 V / GND—1 / 6
Horloge RTC DS3231 : SDA / SCL2 / 33 / 5
LED bleue / verte / rouge (+ résistance 220 Ω)17 / 27 / 2211 / 13 / 15
Buzzer actif148
{% call encadre("attention", "Alimentation du lecteur") %}

Le RC522 se branche en 3,3 V, jamais en 5 V : il serait détruit.

{% endcall %} {% endcall %} {% call etape(3, "Installer le programme") %}

Activez SPI et I2C (sudo raspi-config → Interface Options), copiez le dossier boitier dans /home/pi/boitier, puis :

cd ~/boitier
bash installer.sh
nano .env      # SERVEUR_URL=http://IP_DU_SERVEUR:8000
               # DEVICE_ID=RPI-001
               # API_TOKEN=le token copié à la section 4
sudo systemctl restart pointage-boitier
{% endcall %} {% call etape(4, "Vérifier") %}

La LED bleue fixe indique que le boîtier est prêt et que le serveur répond, et le boîtier apparaît en ligne sur le tableau de bord. Il redémarre ensuite tout seul à chaque branchement.

{% endcall %} {% call encadre("astuce", "Mettre l'adresse IP, pas un nom") %}

Dans SERVEUR_URL, utilisez l'adresse IP du serveur : avec un nom comme localhost, chaque envoi peut perdre 2 secondes (mesuré).

{% endcall %}

6Salles, groupes et règles

{{ capture("a-config-salles", "Configuration : salles, groupes et règles de présence.") }}
  • Salles et groupes sont créés par l'import de l'emploi du temps et des étudiants. On peut les renommer ou en ajouter. Supprimer une salle ou un groupe supprime aussi ses cours (les étudiants sont conservés).
  • Règles de présence (affichées pour information) : badge accepté {{ AVANCE_POINTAGE_MIN }} min avant le cours, retard après {{ TOLERANCE_RETARD_MIN }} min. Elles se règlent dans le .env du serveur (AVANCE_POINTAGE_MIN, RETARD_TOLERANCE_MIN, ICAL_SEMAINES, SEUIL_RISQUE).

{% endcall %} {% call encadre("attention", "Actions irréversibles") %}

Faites une sauvegarde de la base (section 8) avant ces trois opérations.

8Sauvegarder la base

Sur le serveur, dans le dossier du projet :

docker exec sae_postgres_neuf sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/sauvegarde.dump'
docker cp sae_postgres_neuf:/tmp/sauvegarde.dump ./sauvegarde_AAAA-MM-JJ.dump

La restauration (qui remplace les données actuelles) est décrite dans le README du projet. Le fichier contient des données personnelles : gardez-le sur un support sûr, jamais dans le dépôt Git.
